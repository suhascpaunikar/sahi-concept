01 / What changed

Version 1.4 is a feasibility review of v1.3. It keeps every v1.3 decision, fixes the places where v1.3's own numbers or figure didn't hold, and adds what a prototype needs. These are proposed product decisions for the concept, not claims of Sahi approval or completed usability testing. Use this document as one complete revision rather than mixing rules across versions.

02 / Product intent

Problem, users and evidence

Active mobile chart users repeatedly change intervals, inspect indicators and select drawing tools while monitoring two charts. The hypothesis is that a learned hold–slide–release shortcut can reduce repeated menu navigation while keeping a persistent drawing toolbar optional.

Primary users: active Option Scalper users on iOS and Android in portrait. Test both experienced Sahi users and comparable mobile-chart users, both hands, both chart positions, and people who prefer ordinary taps. Live and Practice share shortcut preferences but keep independent chart state.

JobCurrent comparisonProposed benefit / limitation
Change timeframeExisting timeframe-button tap and interval choiceTwo configurable favorites; not a complete replacement for 1m/5m/15m or the full interval list.
Show or turn off an indicatorCurrent indicator menu and applicable existing shortcutsDirect access to one named VWAP preset and one named EMA preset.
Arm Trend Line or FibCurrent drawing menu and favorite drawing toolbarMay reduce navigation when the toolbar is hidden. Speed superiority over a pinned tool is not assumed.
Temporarily simplify the chartCurrent supported hide/show operationsOne reversible visibility mask, with an equally accessible tap action.

Evidence boundaries

  • R1–R3 are author-supplied screenshots of the existing interface. Tap counts and menu-close behavior require confirmation in the current app before they become benchmark baselines.
  • The problem-bank items about strike/lot changes, higher-timeframe context and exact-price drawing are adjacent context. This MVP does not solve strike selection, simultaneous higher-timeframe overlays or precision placement.
  • Sahi documents favorite drawing tools and synchronized timeframes (R7/R8). Verify exact on-screen controls and engine behavior; a screenshot alone does not establish what its Link icon does.
  • Marking-menu research supports directional-menu exploration. This design deliberately retains a hold delay and must earn its own performance claims. The game reference is visual inspiration, not mobile-trading evidence.
Success hypothesis

A meaningful speed improvement on frequent chart actions, without more incorrect commits, with an understandable cancellation path and an effective tap alternative. If the wheel only saves chart space relative to a favorite toolbar, report that tradeoff separately.

Excluded

Prototype ≠ production MVP

The HTML PRD is documentation. Appendix A specifies a separate interaction prototype. That prototype uses mock data and inert order controls; it cannot establish native accessibility, production order-update performance or engine compatibility.

Ordinary route: tap timeframe button → B1 → Quick actions → Q1 → activate an action. This includes Clean View. The extra route is available to everyone; it is not restricted to assistive technology.

Gesture route: hold timeframe button → M1 when geometry qualifies → slide to a visible sector → release. If space does not qualify, hold → “Release here for Quick actions” → release within the invoking button’s hit area → Q1. No chart action applies during this fallback transition.

Q1 includes a footer with Quick wheel settings and Replay tutorial. Q1 has an explicit heading such as “Quick actions · Option chart”. Timeframe rows say “Both charts” when linked. Show the full resulting action, for example “Set both charts to 1m”, “Turn off EMA 20” or “Exit Clean View and show VWAP”. Active timeframes are marked Current and do not mutate state. Q1 closes after a valid command is accepted; unavailable/current rows remain informational and do not close it.

Closing Q1 returns to its invoker: B1 when opened there, or S1 when opened by the hold fallback or accessibility shortcut. Applying an action returns to S1. S2 Back likewise returns to its actual entry surface. B2 dismissal returns to S2 without changes. Sheets never open a second wheel.

Reach and handedness

The timeframe button retains the existing reach requirement; this revision does not claim to solve top-of-phone reach. Test that limitation explicitly. The tap sheet eliminates continuous-drag demands, but still needs an entry point the user can reach. If either hand or chart position fails the study gates, do not expand the wheel rollout; revise placement or reduce gesture scope.

06 / Commit semantics

Action behavior and chart state

Timeframes: staged, scoped and truthful

Selecting a different interval submits one request for the frozen scope: the target chart when unlinked, both charts when linked. Keep the previous interval labels and live chart data visible while loading. Show “Updating timeframe…” in each affected chart's status row (top left of the plot, under the header) and disable additional timeframe commands in M1, Q1 and B1 until completion. Do not queue a second request; an attempted command reports Busy.

Stage the new data without replacing the visible charts. Commit all affected charts and labels in the same UI transaction when every dataset is ready. On any failure or a 10-second timeout, discard staged results, keep all previous intervals and show “Couldn’t load {interval}. Charts unchanged.” Success haptics and “Both charts set to {interval}” occur only after verified application. Use request IDs and chart-generation tokens to ignore late or invalid responses.

Changing instrument, leaving S1, account/session change or changing link scope aborts the pending operation. Drawing cannot start while an affected chart is changing timeframe. Existing open drawings are disarmed when a timeframe command is accepted. Normal live updates continue on the previously applied interval during staging.

With linking enabled, an interval is Current only when all affected charts already use it. If charts initially differ, selecting it brings both to that interval. The wheel reads existing link state and never changes link state. Verify the engine’s initialization and sync behavior before integration; do not guess from the icon.

Indicators: explicit identity

A slot binds to {type: VWAP|EMA, presetId, settingsVersion}; the chart adapter resolves one stable bound instance per chart. Reuse that exact instance when present. Other instances of the same indicator are untouched. If duplicate matching instances make the binding ambiguous, disable the slot with a reason and require resolution in the existing indicator settings; never guess which one to remove.

Initialize named system presets “VWAP · session” and “EMA 20”; settings lets users deliberately bind another supported preset of the same type. The wheel has no independent indicator-parameter editor. Preset deletion/access loss leaves the slot unavailable until reconfigured. Preserve the label and position; do not silently replace it. Preset edits update between gestures; version or capability changes during a gesture cancel it.

Clean View: a reversible visibility mask

Clean View is per chart. It hides indicators and drawings only. Candles, axes, last price, positions, pending orders and SL/TP remain visible and keep updating. Use a separate render-layer mask, not deletion, mass toggling or a snapshot of earlier settings.

Turning Clean View off removes only that mask. Individually hidden objects stay hidden; disabled indicators stay disabled; edits made after entering Clean View are honored. Enabling an indicator explicitly sets its underlying visibility to visible; disabling preserves its settings. If the action fails, enabled state, individual visibility and the clean mask roll back together. The chip “Clean View · overlays hidden” sits in the same status row, in the space the hidden legend frees, and has a ≥48×48 close target; the header is too narrow for it on a 360-wide phone. Mask state resets off when leaving S1, replacing that chart’s instrument, switching Live/Practice or restarting; ordinary background/resume preserves it within the same S1 session.

Explicit show/add actions from B1 follow the same reveal policy. Remove/hide edits from B1 change the underlying state without automatically exiting Clean View. Arming a drawing tool exits Clean View on that chart. If enabling an indicator or arming a tool fails, neither its state nor the clean mask changes. When Clean View is active, indicator status reads “Enabled · hidden by Clean View”, not an unexplained On dot.

Drawing: a separate placement interaction

Only Trend Line and Fibonacci Retracement are supported in this MVP. On successful selection, arm the tool on the chosen chart and show N3: “{Chart} · Trend Line: tap the first point”, then “Tap the second point”. Fib uses its own name and first/second anchor guidance. The wheel release never places an anchor.

Drawing-point taps consume ordinary chart-tap behavior; they do not open the option order panel. Wrong-chart taps place nothing and retain the draft with a brief target reminder. Chart pan/crosshair gestures are suspended on the target while placing points; existing order controls remain their own controls and cannot receive a drawing tap.

Cancel, opening B1/Q1/M1, changing interval/instrument/link scope, leaving S1, app background, second-touch interruption or resizing the target removes only the unfinished draft and disarms the tool. Completed drawings are unaffected. Canceling after the tool has revealed Clean View does not turn Clean View back on. After two valid points, commit the drawing, close N3 and return to ordinary chart interaction.

08 / Stable preferences

Configuration, persistence and availability

S2 shows the actual ordered layout. Users edit Timeframe A and B independently; values must be unique and supported by the existing interval catalog. There is no automatic sorting. Trend, Fib and Clean View are read-only rows. VWAP and EMA choose one compatible named preset each. There are no empty slots, arbitrary catalog tabs or “+ Add” destinations in MVP.

Store a versioned configuration per signed-in account on this device. Live and Practice share these preferences; indicator enabled states, drawings and Clean View remain chart/session-specific. No cross-device synchronization is promised. Save locally and atomically before showing success. If writing fails, keep the previous persisted configuration and show “Couldn’t save. Your previous shortcuts are unchanged.”

Offline preference changes are allowed from a validated cached catalog. Entries without known support/settings are disabled. Load validated preferences before configurable slots can apply. Unknown or corrupted returning-user configuration disables the four configurable slots (Timeframe A and B, VWAP and EMA) in M1 and Q1 and offers Retry or confirmed Reset in Q1 and S2. Trend, Fib and Clean View don't depend on preferences and keep working, and the ordinary B1 menu still works. Do not quietly initialize defaults for a returning user.

Reset confirms “Reset quick wheel? Timeframes go back to 1m and 5m, and indicators to VWAP · session and EMA 20. Trend, Fib and Clean View don't change.” and replaces preferences in one atomic write. A failed reset changes nothing. Reset does not reset onboarding acknowledgement. Switching accounts or signing out cancels active gestures and clears the previous account’s in-memory configuration.

11 / Evidence plan

Measurement and study design

EventDefinition
quick_action_startEarliest input required to reach the action from S1, including the initial timeframe-button input before B1. Create one interaction ID and preserve it through B1 → Q1 → application. Q1 opening never restarts the timer. A direct accessibility invocation starts at that invocation.
quick_action_openWheel/menu/sheet first visible; record route, fallback, availableR, eligibility and opening latency.
quick_action_commitValid release or actionable tap; record intended semantic action, chart scope and monotonic timestamp.
quick_action_appliedAdapter verifies the requested state rendered. Drawing selection completes here when the correct tool is armed.
quick_action_failedAccepted command did not apply; reason and elapsed time. Keep distinct from a user cancel.
quick_action_cancelReason: prehold_move, inner, separator, outside, current, unavailable, interrupted, invalid_context or dismissed. For separator and outside, also record the nearest slot and whether the release was within 10° beyond a fan edge (edge-slot misses).
drawing_completedSeparate timestamp for the final completed drawing; never substitute it for tool-arming time.
quick_wheel_preferences_savedVersion and outcome only; used to associate a layout snapshot, not to infer trading behavior.

Common fields: interaction ID, research trial ID when applicable, route, logical chart identifier, affected scope, item/preset ID, layout version, viewport/panel size, outcome/reason and monotonic timestamps. Do not log instrument symbols, balances, orders, screenshots or placed drawing prices. In the prototype, logs stay local; an explicit Export log action downloads JSON.

Primary duration: verified applied − initial input. A research trial ID spans retries so recovery time is not discarded. Report successful-attempt durations alongside all-trial completion/failure counts and total task time with a predeclared timeout. Report median and P90 per job, route, chart position, platform and tested hand. Keep tool-arming and completed-drawing measures separate.

Quick cancel within one second means “quick cancellation”, not “accidental open”. Determine accidental behavior in intended-tap trials and observation. Immediate reversals in beta are only a diagnostic proxy. Adoption uses eligible users actually exposed to the feature; report second-week repeat use. Toolbar reduction is secondary and must be paired with unchanged or improved drawing success.

Eligibility exposure: report the share of holds that open the wheel versus Q1, by frame, order-panel state and chart. A wheel result describes eligible layouts only; report fallback completions separately.

Formative study: proposed protocol

  1. Recruit 12 active mobile-chart users: six frequent Sahi scalpers and six comparable users, including at least three left-handed users. This is problem discovery, not population proof.
  2. Observe an unprompted first encounter before teaching; then give equal practice for wheel, tap sheet, current menus and existing favorite toolbar where applicable. Counterbalance route/task order.
  3. Use mock/replayed markets and inert order controls. Test both chart positions, order panel open/closed, minimum and resized panels, a small Android phone, a normal iPhone and a large phone. Include one-handed and preferred-hand use.
  4. Test intended cancellation, ordinary taps, indicator hidden-state cases and failure recovery. Repeat a subset after 48–72 hours to assess unaided recall.

Benchmark: proposed protocol

After formative fixes, recruit at least 24 target users across iOS/Android; use pilot variance to set the final sample before making population claims. Predeclare frequent jobs and the fastest applicable existing comparator for each. Match starting state, data delay, rendering delay and practice. Include at least 20 intended ordinary taps per participant, separately from intended holds. Analyze paired participant-level results and uncertainty; do not treat hundreds of repeated taps from a few people as hundreds of independent users.

Accessible interaction detail

When VoiceOver/TalkBack is active, suppress custom hold recognition. Normal activation opens B1; its visible Quick actions row opens Q1. A native “Quick actions” custom action may open Q1 directly, but is supplementary. Q1 has a named heading, stable item order, spoken scope/state/reason and no forced timeout. Escape/system Back closes it; dismissing returns focus to its invoker, applying returns focus to the originating chart control. Announce actual results without claiming success early.

At 200% text or a user preference for tap controls, route to Q1 rather than compressing wheel labels. Both Q1 and B1 scroll as needed. Reduced motion removes pressed-button and wheel scaling; no-haptic mode retains full visual and spoken feedback.

13 / Decision discipline

Release gates, risks and ownership

Targets are proposals, not results

The sample sizes, thresholds and budgets below are author-proposed gates for review before testing. No study or device result is claimed. A zero-event scripted test is not proof that an error can never occur.

StageGate / response
G1 · Formative exitAt least 11/12 participants complete each taught core action and intentional cancellation without assistance. Every observed false commit, wrong-chart effect or boundary misunderstanding is resolved and the affected case retested. Demonstrate the tap alternative for anyone unable to perform the gesture.
G2 · Benchmark decisionProposed: ≥20% median improvement on at least two predeclared frequent jobs versus the fastest applicable existing path; ≥95% task completion; ≤2% wrong-action commits and no worse than comparator; P90 no worse for claimed improved jobs. Zero unintended commits observed in scripted ordinary-tap trials. Examine each tested hand/platform/chart position and report eligible and fallback layouts separately; do not hide a failing group in the aggregate.
G3 · Native readinessAll AC cases pass on supported iOS/Android, including native assistive technology and production chart adapters. Confirm staged linked changes, stable preset identity and update performance on actual engine integrations.
G4 · Opt-in betaProposed 50 eligible users for two weeks, behind a feature flag and kill switch. Review verified outcomes, errors, repeat use and qualitative feedback. Adoption alone is not expansion approval.
Stop / reviseAny attributable underlying order/control activation, wrong-chart mutation, lost preferences or disappearance of protected information stops rollout. Resolve and retest. Geometry/accuracy failure means revise sector count or placement; do not relax hit rules invisibly.

A feature that matches the favorite toolbar on speed but reduces persistent chart coverage may justify a narrower optional release. That requires an explicit product decision supported by evidence; it cannot be counted as a speed win against a deliberately slower menu baseline.

Open decision OD-1 · owner: product and design

With the order panel open on a standard phone, neither chart qualifies for the wheel. Proposal: let the index chart's wheel extend down over the option chart, measuring its bounds from the top of the index panel to the bottom of the option panel and never into the order panel, and keep the target-chart outline on the index panel. The top chart would then qualify in every layout in Section 5; the option chart stays Q1-only while the order panel is open. Cost: the fan covers the option chart's latest candles for the length of the hold, and the outline has to carry the scope on its own. Decide before the benchmark. The prototype has a toggle for it, off by default, so v1.3's rule stays the baseline.

Residual risks to test

  • Seven narrow directions may still be harder than taps despite adequate nominal target geometry. Measure adjacent-slot errors and hand effort.
  • A large fan temporarily covers chart content; translucency does not guarantee readable candles. Measure task disruption and time spent obscuring the chart.
  • The hold delay may erase savings for timeframes and pinned drawing tools. Preserve the ordinary path and use the fastest relevant baseline.
  • The current button may be difficult to reach on a large phone. The tap alternative addresses dragging, not reach; placement needs another revision if testing fails.
  • Fallback is expected on standard phones whenever the order panel is open (Section 5), which is when traders are most likely to be mid-trade. Track exposure and completion by layout so a nominal “wheel” success does not hide dependence on Q1.
  • With no clamping, the edge slots (Timeframe A and Clean View) cancel if a straight-left or straight-down slide drifts just past the fan edge. Measure edge misses alongside adjacent-slot errors before changing the rule.

Canonical hit-test pseudocode

hit(point, frozenGeometry):
  r, theta = polar(point - anchor)
  if r < 120 or r > R: return NONE
  for i in 0..6:
    low  = 180 - (i + 1) * 90/7 + 0.5
    high = 180 - i * 90/7 - 0.5
    if low < theta and theta < high: return i
  return NONE
onPointerUp(point):
  if sequenceWasCanceled: consume; return
  if state == WHEEL:
    slot = hit(point, frozenGeometry)
    if slot is available and not current: dispatch(slot)
    else: cancel()
  if state == FALLBACK:
    if point is inside originalButtonHitRect: open Q1
    else: cancel()
